# Sunny Tea House · 茶饮评价助手

一个可以直接运行的 Vue 3 + Node.js 项目。虚构店铺位于 San Jose，采用奶油底色、茶绿按钮和日光黄细节，支持桌面与手机。

**在线演示（Demo）**：https://tyza66.github.io/sunny-tea-house/ 。静态演示托管没有 `/api` 时会自动回退到本地示例文案，手机打开即可完整体验“选感受 → 选平台 → 生成 → 编辑 → 复制并跳转”的闭环；接入真实 DeepSeek 后仍走服务端接口。

**Netlify 真实 AI 接入已添加**：按 [Netlify 接入 DeepSeek](docs/Netlify接入DeepSeek.md) 在后台配置 Key，并双击 `部署到Netlify.cmd` 完整更新前端和函数。

## 1. 先启动演示，不需要任何账号或密钥

1. 打开项目根目录。
2. 双击 **启动项目.cmd**。首次运行会根据 `.env.example` 创建本地 `.env`；依赖缺失时自动安装，然后构建页面。
3. 等窗口出现服务地址，在浏览器打开 **http://127.0.0.1:4318**。
4. 保持窗口打开。停止时在该窗口按 `Ctrl+C`。
5. 选择 1–2 个标签 → 选择平台 → 生成 → 修改文案 → 勾选真实体验确认 → 复制。

需要 Node.js 22 或以上版本。当前项目已安装依赖并完成构建；移到其他电脑时仍建议安装 Node.js 24 LTS。

**默认演示模式不会调用 DeepSeek，也不会发送企业微信消息。** 示例内容由本地模板生成，并在页面明确标记。店铺是虚构的，所以没有伪造 Google 商家链接。

## 2. 核心功能

**新增多语言**：顶部切换界面语言，平台下方选择评价语言。支持简体中文、繁體中文、English、Français (Canada)、Español。首次访问参考浏览器语言；手动选择后保存在当前浏览器。界面语言和评价语言相互独立，切换界面不会清空或翻译已有草稿。详见 [多语言使用与维护](docs/多语言使用与维护.md)。

| 功能 | 实现与边界 |
| --- | --- |
| 感受标签 | 6 个标签，最多选 2 个；前端与后端均校验 |
| Google | 默认英文，可选五种语言；自然简短，提示词要求 3–4 句 |
| 小红书 | 默认简体中文，可选五种语言；分段与 Emoji，所有语言均校验不超过 150 个 Unicode 字符 |
| 编辑初稿 | 可修改；修改后需要重新勾选真实体验确认 |
| 重新生成 | 成功后替换初稿；失败保留已有编辑内容 |
| 切换标签、平台或评价语言 | 标记初稿已过期，重新生成后才能复制；界面语言不影响初稿 |
| 复制与跳转 | 复制成功后打开配置的链接；不会自动发布 |
| 复制失败 | 选中文案，提供手动复制说明和平台链接 |
| 企业微信 | 可选：服务端异步生成中文摘要与店家回复草稿，再通知群机器人；默认关闭 |
| 访问限制 | 每个来源 IP 每分钟最多 10 次生成请求，限制存于当前进程 |

## 3. 接入真实 DeepSeek：逐步操作

1. 打开项目根目录 `.env`。文件不存在时，把 `.env.example` 复制一份并重命名为 `.env`。
2. 在 DeepSeek 开放平台创建 API Key，并确认账户可以调用 API。
3. 修改下面两项，等号左右无需空格：

   ```dotenv
   DEMO_MODE=false
   DEEPSEEK_API_KEY=在此填写你自己的完整密钥
   ```

4. 保持 `DEEPSEEK_MODEL=deepseek-chat`，或填写你账号支持的模型。
5. 保存文件，停止原服务，再双击启动文件。
6. 页面文案应从“当前使用示例文案，不会调用 AI 服务。”变为“AI 帮你起稿，真实感受由你把关。”，初稿标记从“演示初稿”变为“AI 初稿”。生成一条初稿确认接入成功。

密钥只能放服务端 `.env`；不要放到 Vue、浏览器请求中，也不要使用 `VITE_` 前缀。字符串拆分、Base64 等处理都不能保护前端密钥。`.gitignore` 已忽略 `.env`。

服务端调用 `https://api.deepseek.com/chat/completions`。原代码中的 `https://deepseek.com` 是网站地址，不是聊天补全接口。

## 4. 补全店铺与平台入口

1. 修改 `.env` 中的 `STORE_NAME`、`STORE_CITY`。
2. 如果以后用于真实商家，从 Google 商家后台复制“索取评价”链接，填入 `GOOGLE_REVIEW_URL`。
3. 没有真实商家链接时，保持空白。界面只提供复制，不会跳转到一个不对应的商家。
4. `XIAOHONGSHU_URL` 默认是小红书官网；可以改成可信的小红书官方链接。
5. 重启服务，再检查网页。

小红书默认入口不是笔记编辑器。是否唤起 App、是否需要登录由浏览器和平台决定；网页没有承诺跨设备直接打开发布页。Google 也需要用户登录、粘贴并亲自提交。

## 5. 可选企业微信通知

1. 在你有权限管理的企业微信群创建机器人，取得 Webhook URL。
2. 在 `.env` 填入 `WECHAT_WEBHOOK_URL`。
3. 将 `ENABLE_WECHAT_NOTIFY` 改成 `true`，同时确认 `DEMO_MODE=false`。
4. 重启服务。界面会提示生成初稿会同步给店家。
5. 手动生成一条真实初稿，检查群里的通知。

开启后，评价生成成功会再调用一次 DeepSeek，产生中文摘要与店家回复草稿；这会增加 API 用量。群消息标注“评价初稿 · 尚未发布”，因为系统无法判断用户是否真的在平台发布。用户后续编辑不会自动同步。机器人 URL 和 Key 一样需要保密。

当前采用进程内异步发送，不阻塞评价结果；发送失败在服务窗口记录，**没有持久化队列或自动补发保证**。需要稳定商用通知时，按架构文档中的扩展方案加入队列。

## 6. 开发、构建与检查

在项目目录打开 PowerShell：

```powershell
npm.cmd ci
npm.cmd run dev
```

开发界面为 `http://127.0.0.1:4317`，后端为 `127.0.0.1:4318`。开发模式统一使用这两个端口；如果要改端口，请同时修改 `scripts/dev.mjs` 和 `vite.config.js`。

```powershell
npm.cmd test
npm.cmd run build
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

浏览器测试使用独立的 `4320` 端口，演示模式运行，不使用真实密钥，不访问外部发布平台，不发送群消息。测试前先构建。

生产形式的本地运行：

```powershell
npm.cmd run build
npm.cmd start
```
