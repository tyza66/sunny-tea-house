# Sunny Tea House · 茶饮评价助手

面向茶饮店的顾客评价助手，虚构店铺位于 San Jose，服务“到店消费之后想写点什么”的场景。它把顾客的真实感受整理成可编辑、可核对的评价初稿：选 1–2 个感受标签与发布平台，AI 按平台口吻和所选评价语言起稿，顾客二次编辑、勾选确认真实体验后一键复制并跳转对应平台，由用户本人发布。系统不代发任何内容，也不替顾客虚构没有发生的体验。

Vue 3 + Vite 前端、Node 22 + Express 5 服务端，另有一条 Netlify Functions 路径。代码不依赖本地启动，只在两个平台运行：`https://tyza66.github.io/sunny-tea-house/` 静态演示，以及按 [接入 AI 服务商](docs/AI服务商接入.md) 在 Netlify 配置环境变量后的真实 AI 部署；仓库里没有 `.env`、启动脚本等只在本地运行的文件。界面取「宣纸墨」素雅极简：宣纸底、暖墨字、发丝墨线，全站唯一信号色是印章朱砂，标题用衬线细字重，配一枚楷体阴刻的“茶”字小印，桌面与手机一致可用。

**关键设计取舍**

- **一份提示词，两端共用**：写作约束集中在 `shared/prompt.js`，服务端与浏览器直连两条生成路径读同一份规则，避免同一功能两种口吻。
- **界面语言与评价语言解耦**：界面五种语言（简体、繁體、English、Français (Canada)、Español）与评价输出语言各自独立，切换界面语言不清空、不翻译已有草稿。
- **错误归一化为文案键**：服务端只回中文提示与状态码，`shared/languages.js` 的 `ERROR_KEYS` 映射成稳定键，切换界面语言时已有错误即时更新。
- **CSP 按部署模式派生**：真实模式 `connect-src` 只放行 `AI_BASE_URL` 一个来源；演示模式放行所有 HTTPS，匹配评审者可在面板自填任意 OpenAI 兼容服务商的行为。
- **密钥不进前端产物**：服务端只从环境变量读密钥；静态演示侧由评审者填自己的服务与密钥，浏览器直连该服务商、不经本站，本机混淆保存、明文显示、可随时清除。
- **文案长度按字符收敛**：小红书所有语言均校验不超过 150 个 Unicode 字符，超限时服务端自动重写一次，仍超限则明确报错而非截断。

**质量与验证**

- 单元测试 58 项（`npm test`，纯 Node，覆盖接口契约、语言白名单、静态回退与浏览器直连逻辑）；Playwright 端到端 25 项（`npm run test:e2e`，覆盖五语言、深浅主题、设置面板与手机视口无横向溢出）。
- GitHub Actions 每次推送自动执行 `npm ci` → `npm test` → `npm run test:e2e` → `npm run build`，单测与端到端任一不通过都不发布；线上 Pages 资源哈希与本地 `dist/` 一致。
- 端到端门禁补的是单测的盲区：纯逻辑测试不会真正执行 `App.vue` 的 setup，组件级运行时报错（如引用尚未声明的响应式变量导致整页白屏）只有真实浏览器能发现。
- 交付文档、架构设计、修复与维护手册、验证记录随代码同步维护，界面预览图由端到端测试生成后入库，见第 7 节「项目资料」。

## 1. 在线运行方式

本项目只在两个平台运行，都不需要本地启动服务。

**GitHub Pages（静态演示，代码推送即发布）**

- 推送 `main` 后由 `.github/workflows/pages.yml` 自动执行 `npm ci` → `npm test` → `npm run build`，把 `dist/` 发布为 Pages。
- 没有服务端接口，页面自动回退本地示例文案，并明确标注演示模式；右下角「本地设置」按钮即本机配置入口，见上一段说明。
- 工作流已内置 `npm test` 与 `npm run test:e2e` 两道门禁：单测不通过不发布，端到端不通过同样不发布。

**Netlify（真实 AI，前端 + 服务端函数）**

- 由 `netlify.toml` 指定构建命令 `npm run build:netlify`，产物在 `out/`，函数来自 `netlify/functions`。
- Netlify 端固定真实模式（演示开关已在该路径关闭），密钥只从 Netlify 环境变量读取；未配置会直接报错而不是静默降级。
- 后续修改源码推送到仓库，Netlify 关联仓库后自动重新构建；环境变量改动后需要触发一次重新部署，详见 [接入 AI 服务商](docs/AI服务商接入.md)。

**默认演示模式不会调用 DeepSeek，也不会发送企业微信消息。** 示例内容由本地模板生成，并在页面明确标记。店铺是虚构的，所以没有伪造 Google 商家链接。

## 2. 核心功能

**新增多语言**：顶部切换界面语言，平台下方选择评价语言。支持简体中文、繁體中文、English、Français (Canada)、Español。首次访问参考浏览器语言；手动选择后保存在当前浏览器。界面语言和评价语言相互独立，切换界面不会清空或翻译已有草稿。详见 [多语言使用与维护](docs/多语言使用与维护.md)。

| 功能 | 实现与边界 |
| --- | --- |
| 感受标签 | 6 个标签，最多选 2 个；前端与后端均校验 |
| 简单点评 | 选填，25 个 Unicode 字符以内、可留空；输入框限制长度，服务端按字符数兜底校验并给出中文提示 |
| Google | 默认英文，可选五种语言；自然简短，提示词要求 3–4 句 |
| 小红书 | 默认简体中文，可选五种语言；分段与 Emoji，所有语言均校验不超过 150 个 Unicode 字符 |
| 编辑初稿 | 可修改；修改后需要重新勾选真实体验确认 |
| 重新生成 | 成功后替换初稿；失败保留已有编辑内容 |
| 切换标签、平台、评价语言或点评 | 标记初稿已过期，重新生成后才能复制；界面语言不影响初稿 |
| 复制与跳转 | 复制成功后打开配置的链接；不会自动发布 |
| 复制失败 | 选中文案，提供手动复制说明和平台链接 |
| 企业微信 | 可选：服务端异步生成中文摘要与店家回复草稿，再通知群机器人；默认关闭 |
| 访问限制 | 每个来源 IP 每分钟最多 10 次生成请求，限制存于当前进程 |

## 3. 接入真实 AI：在 Netlify 配置

本项目通过一组通用的 `AI_*` 环境变量对接任何 **OpenAI 兼容**服务商，默认值即 DeepSeek，换服务商只改变量、不改代码。

1. 登录 Netlify，进入项目 **Project configuration → Environment variables**。
2. 添加下面的变量（Scope 需包含 Functions，上下文选 Production 或全部）：

| Key | Value | 说明 |
| --- | --- | --- |
| DEMO_MODE | false | Netlify 路径固定真实模式 |
| AI_API_KEY | 你的完整 API Key | 只由服务端函数读取，绝不发给浏览器 |
| AI_BASE_URL | https://api.deepseek.com | 可选，换服务商时只改这一行 |
| AI_MODEL | deepseek-v4-flash | 可选，服务商支持的模型名 |

3. 旧部署里的 `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` 仍作别名有效；新配置建议直接写 `AI_*`。
4. 保存后触发一次重新部署，让函数读到新值。
5. 页面文案应从“当前使用示例文案，不会调用 AI 服务。”变为“AI 帮你起稿，真实感受由你把关。”，初稿标记从“演示初稿”变为“AI 初稿”。生成一条初稿确认接入成功。

常用服务商的 `AI_BASE_URL` 示例、密钥无效时的排查顺序，以及「确认生效」的检查步骤都在 [接入 AI 服务商](docs/AI服务商接入.md)。

密钥只能放 Netlify 环境变量；不要放到 Vue、浏览器请求中，也不要使用 `VITE_` 前缀。字符串拆分、Base64 等处理都不能保护前端密钥。

静态演示（GitHub Pages）是例外场景：店家没有密钥，由评审者在设置面板里填**自己的**服务与密钥，浏览器直连该服务商完成生成；密钥不过本站服务器，在本机以混淆形式保存、明文显示，可随时清除。

服务端默认调用 `https://api.deepseek.com/chat/completions`；换服务商时由 `AI_BASE_URL` 指定地址，代码只认 OpenAI 兼容协议（`/chat/completions` + `Bearer` 认证）。注意区分：`https://deepseek.com` 是官网地址，不是聊天补全接口。

## 4. 补全店铺与平台入口

同样在 Netlify 环境变量中修改，保存后重新部署：

| Key | 说明 |
| --- | --- |
| STORE_NAME / STORE_CITY | 店名与城市 |
| GOOGLE_REVIEW_URL | Google 商家后台“索取评价”链接；留空则默认跳 Google 地图搜索该店 |
| XIAOHONGSHU_URL | 默认小红书官网，可改成可信的小红书官方链接 |

小红书默认入口不是笔记编辑器。是否唤起 App、是否需要登录由浏览器和平台决定；网页没有承诺跨设备直接打开发布页。Google 也需要用户登录、粘贴并亲自提交。

## 5. 可选企业微信通知

1. 在你有权限管理的企业微信群创建机器人，取得 Webhook URL。
2. 在 Netlify 环境变量填入 `WECHAT_WEBHOOK_URL`。
3. 将 `ENABLE_WECHAT_NOTIFY` 改成 `true`，同时确认 `DEMO_MODE=false`。
4. 重新部署。界面会提示生成初稿会同步给店家。
5. 手动生成一条真实初稿，检查群里的通知。

开启后，评价生成成功会再调用一次所配置的 AI 服务商（默认 DeepSeek），产生中文摘要与店家回复草稿；这会增加 API 用量。群消息标注“评价初稿 · 尚未发布”，因为系统无法判断用户是否真的在平台发布。用户后续编辑不会自动同步。机器人 URL 和 Key 一样需要保密。

当前采用进程内异步发送，不阻塞评价结果；发送失败只在服务端记录，**没有持久化队列或自动补发保证**。需要稳定商用通知时，按架构文档中的扩展方案加入队列。

## 6. 构建与检查

GitHub Actions 已在每次推送时自动执行，无需本地操作：

```text
npm ci         安装依赖
npm test        纯 Node 单元测试（CI 门禁，不通过不发布）
npm run build   生产构建，产物 dist/
```

浏览器端到端测试与文档截图在需要时执行：`npm run test:e2e`（需要先构建，使用独立端口与演示模式，不访问真实密钥、不外发消息）。界面预览图（手机/桌面/法语/生成结果）由该测试生成，已随仓库入库，可直接在交付文档中引用。

Netlify 侧由 `netlify.toml` 执行 `npm run build:netlify`，产物与函数一并部署。

交付文档的 PDF 由 `scripts/render-pdf.mjs` 从 Markdown 渲染：改完 `docs/交付文档.md` 后执行 `npm run docs:pdf`，即可重新生成 `docs/交付文档.pdf`（渲染用的浏览器已随开发依赖安装，无需额外准备）。
