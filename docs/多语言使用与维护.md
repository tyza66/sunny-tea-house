# 多语言使用与维护

## 支持范围

| 语言 | 标识 | 界面 | 评价生成 |
| --- | --- | --- | --- |
| 简体中文 | zh-CN | 支持 | 支持 |
| 繁體中文 | zh-TW | 支持 | 支持 |
| English | en | 支持 | 支持，提示词采用北美表达 |
| Français (Canada) | fr-CA | 支持 | 支持，提示词指定加拿大法语 |
| Español | es | 支持 | 支持，提示词采用北美西班牙语 |

## 具体操作

1. 在页面顶部的“界面语言 / Display language”下拉框选择语言。语言名称以各自的原文显示，便于用户找到熟悉的语言。
2. 标题、标签、按钮、说明和错误提示会立即切换；已经输入的评价原文保持不变。
3. 在平台下方的“评价语言 / Review language”选择文案输出语言。
4. “按平台默认”保持原规则：Google 用英语，小红书用简体中文。选择其他语言可以覆盖该规则。
5. 选标签、生成、编辑并核对后复制。更改输出语言需要重新生成，避免误复制旧语言的文案。

示例：加拿大用户可以用法语界面，为 Google 生成英语评价；华人用户也可以用繁体界面生成法语文案。

## 偏好与草稿

首次访问参考浏览器的语言偏好：英文、法语、西班牙语匹配对应语言；中文的台湾、香港、澳门或 Hant 标识匹配繁体。未匹配的语言回退到英语。

手动选择保存为浏览器 localStorage 中的 `sunny.uiLanguage` 与 `sunny.reviewLanguage`，下次打开或刷新会恢复。存储受限时本次仍能切换，但无法保证下次记忆。只保存语言偏好，不保存草稿和密钥。

切换界面语言会保留草稿和确认状态。切换输出语言会要求重新核对/生成。刷新仍会清空草稿，这是现有项目行为。

## 架构与代码位置

- `shared/languages.js`：前后端共享语言白名单、平台默认语言和错误文案键映射。
- `src/messages.js`：五种语言的集中式文案表，按简体、繁体、英语、加拿大法语、西班牙语排列。
- `src/i18n.js`：浏览器语言匹配、本地偏好保存、翻译查找与 HTML `lang` 属性更新。
- `src/App.vue`：两个语言选择器；界面语言不参与草稿签名，评价语言参与签名；textarea 标记实际文案语言。
- `server/reviews.js`：校验语言参数，根据平台选文风、根据语言选输出；演示模板同样支持五种语言。
- `tests/languages.test.js`、`tests/e2e/language.spec.js`：语言白名单、文案完整性、全部标签组合、界面交互与偏好保存验证。

`POST /api/reviews` 新增可选 `language` 字段，支持上述五种标识及 `auto`；省略时仍采用旧的按平台默认行为。响应增加实际使用的 `language`。

```json
{ "platform": "Google", "tags": ["服务好"], "language": "fr-CA" }
```

## 限制与维护

- 小红书仍执行本项目的 150 个 Unicode 字符限制，英文、法语、西班牙语也计入空白和标点。这是项目限制，不是对平台官方长度的声明。
- 企业微信摘要与店家回复草稿仍保持中文，方便店家内部阅读；顾客评价原文保留所选语言。
- 本轮已验证演示输出和真实请求的提示词逻辑，未使用真实 DeepSeek Key 验证每种语言的生成质量。
- 新增语言时同步补齐白名单、整列界面文案、演示模板和测试，再构建并重启服务。
- 扩展或重排语言顺序时必须同步 `messages.js` 的列顺序，避免语言错位。
