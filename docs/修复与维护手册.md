# 修复与维护手册

## 一、先保留现场

1. 记录打开的网址、操作步骤、错误提示和发生时间。
2. 如有手工编辑的评价，先复制到本地保存；刷新会清空页面草稿。
3. 部署平台（GitHub Actions / Netlify）的构建与函数日志能看到服务端错误：Actions 看 workflow run 的步骤输出，Netlify 看 Functions 日志。
4. 不要对外发送 API Key 或完整 Webhook URL。

## 二、常见故障

| 现象 | 排查与修复 |
| --- | --- |
| 构建失败（Actions 或 Netlify） | 看对应平台本次构建日志；依赖安装失败多为网络问题，重跑一次 workflow 或触发 Netlify 重新部署 |
| 页面打不开或还是旧版本 | 确认该次推送的 Actions run 与 Netlify deploy 都已 successful；GitHub Pages 发布有几分钟延迟，可强制刷新绕过缓存 |
| 页面只剩页头、内容全白 | 打开浏览器控制台看报错。组件 `setup` 的运行时错误（例如用到尚未声明的变量）会让整页空白，而构建与单元测试都照样通过。执行 `npm run test:e2e` 可稳定复现，按报错行号修复 |
| 一直显示演示体验 | 检查 Netlify 环境变量 `DEMO_MODE=false` 且 Scope 含 Functions；改过变量要重新部署，只刷新网页不生效
| 提示密钥无效 | 检查 `AI_API_KEY`（旧名 `DEEPSEEK_API_KEY` 仍有效）是完整密钥、没有占位文字；换过服务商时再核对 `AI_BASE_URL` 与 `AI_MODEL`；必要时在提供方重新创建 |
| 提示余额不足 | 检查所配置 AI 服务商账户的 API 余额与调用权限（默认为 DeepSeek） |
| 提示操作频繁 | 等待一分钟；当前进程对每个 IP 每分钟限制 10 次 |
| 网络错误或生成超时 | 检查到所配置 AI 服务商（`AI_BASE_URL`，默认 `api.deepseek.com`）的连接；已有草稿会保留，可以稍后重试 |
| Google 按钮只有复制 | 这是未配置 `GOOGLE_REVIEW_URL` 时的正常行为；在 Netlify 环境变量填写真实商家入口后重新部署 |
| 无法自动复制 | 使用 localhost 或 HTTPS；按提示 Ctrl+C/手机长按复制，手动打开平台 |
| 没有弹出平台 | 检查浏览器弹窗设置；使用页面的“手动打开”链接 |
| 更换标签后不能复制 | 旧初稿与当前选择不同，重新生成即可 |
| 修改后复制按钮变灰 | 重新核对并勾选确认；小红书还需不超过 150 字符 |
| 企业微信没有通知 | 检查 `ENABLE_WECHAT_NOTIFY=true` 与 Webhook 地址；在 Netlify Functions 日志查看；通知只发生在初稿生成后 |
| 修改代码后页面没变化 | 推送后等 Actions 与 Netlify 两个平台的构建都跑完；Pages 有 CDN 缓存，强制刷新或多等几分钟 |

## 三、修改位置

- 改颜色、间距、手机布局：`src/style.css`。
- 改交互和页面文字：`src/App.vue`。
- 改感受标签：`server/reviews.js` 的 `TAGS`。演示模式同时更新 `demoReview` 的英文映射。
- 改 AI 语气：`server/reviews.js` 的 `buildMessages`，保留真实体验约束。
- 改简单点评字数上限：`shared/languages.js` 的 `COMMENT_MAX`，服务端校验与界面计数共用同一常量，改一处即两端一致。
- 改店名和平台链接：Netlify 环境变量 `STORE_NAME`/`STORE_CITY`/`GOOGLE_REVIEW_URL`/`XIAOHONGSHU_URL`，修改后重新部署。
- 改通知格式：`server/reviews.js` 的 `notifyWechat`。
- 改限流策略：`server/app.js`，公网方案还需结合部署环境评估。

关键逻辑已有中文注释。小范围修复应优先修改对应模块，避免同时大幅改动页面与服务端。

## 四、修复后的回归步骤

1. 本地或 CI 执行 `npm test`，确认服务端校验、上游错误和通知逻辑通过（GitHub Actions 每次推送都会跑，不通过不发布）。
2. 改了 `App.vue`、`i18n.js`、`api.js` 等前端运行时代码后，必须执行 `npm run test:e2e`（首次使用先 `npx playwright install chromium`）：纯逻辑单测不会执行组件 `setup`，白屏类问题只有端到端能发现，CI 已在构建前内置这道门禁。
3. 执行 `npm run build`，确认 Vue 构建通过。
4. 检查 `docs` 下的桌面和手机截图；布局没有拥挤或横向滚动。
5. 真实 AI 或通知相关修改，在自己的配置环境下各做一次手动验证；自动测试使用模拟响应，不能代替真实服务联调。
