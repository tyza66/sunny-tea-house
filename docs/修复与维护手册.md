# 修复与维护手册

## 一、先保留现场

1. 记录打开的网址、操作步骤、错误提示和发生时间。
2. 如有手工编辑的评价，先复制到本地保存；刷新会清空页面草稿。
3. 查看启动窗口的错误提示。
4. 不要对外发送 `.env`、API Key 或完整 Webhook URL。

## 二、常见故障

| 现象 | 排查与修复 |
| --- | --- |
| 双击后提示没有 Node.js | 安装 Node.js 22+，重新打开窗口后启动 |
| 安装依赖失败 | 检查网络；在项目目录执行 `npm.cmd ci`，不要修改其他工具的全局依赖 |
| 页面打不开 | 保持启动窗口开启；检查地址是否为窗口显示的端口；查看 `/api/health` 是否返回正常 |
| 端口被占用 | 不结束未知进程。在 `.env` 改 `PORT=4321` 后重新启动，访问新端口 |
| 开发模式端口冲突 | 开发模式固定 4317/4318；需同时修改 `scripts/dev.mjs` 和 `vite.config.js` 的端口、代理目标 |
| 一直显示演示体验 | 检查 `.env` 中 `DEMO_MODE=false`，保存后重启；不要修改 `.env.example` 代替生效文件 |
| 提示密钥无效 | 检查 `DEEPSEEK_API_KEY` 是完整密钥、没有占位文字；必要时在提供方重新创建 |
| 提示余额不足 | 检查 DeepSeek 账户的 API 余额与调用权限 |
| 提示操作频繁 | 等待一分钟；当前进程对每个 IP 每分钟限制 10 次 |
| 网络错误或生成超时 | 检查到 `api.deepseek.com` 的连接；已有草稿会保留，可以稍后重试 |
| Google 按钮只有复制 | 这是未配置 `GOOGLE_REVIEW_URL` 时的正常行为；填写真实商家入口后重启 |
| 无法自动复制 | 使用 localhost 或 HTTPS；按提示 Ctrl+C/手机长按复制，手动打开平台 |
| 没有弹出平台 | 检查浏览器弹窗设置；使用页面的“手动打开”链接 |
| 更换标签后不能复制 | 旧初稿与当前选择不同，重新生成即可 |
| 修改后复制按钮变灰 | 重新核对并勾选确认；小红书还需不超过 150 字符 |
| 企业微信没有通知 | 检查真实模式与通知开关；核对 Webhook；查看启动窗口；通知只发生在初稿生成后 |
| 修改代码后页面没变化 | 普通启动需重新构建；双击启动文件会自动构建；开发调试可用 `npm.cmd run dev` |

## 三、修改位置

- 改颜色、间距、手机布局：`src/style.css`。
- 改交互和页面文字：`src/App.vue`。
- 改感受标签：`server/reviews.js` 的 `TAGS`。演示模式同时更新 `demoReview` 的英文映射。
- 改 AI 语气：`server/reviews.js` 的 `buildMessages`，保留真实体验约束。
- 改店名和平台链接：`.env`，修改后重启。
- 改通知格式：`server/reviews.js` 的 `notifyWechat`。
- 改限流策略：`server/app.js`，公网方案还需结合部署环境评估。

关键逻辑已有中文注释。小范围修复应优先修改对应模块，避免同时大幅改动页面与服务端。

## 四、修复后的回归步骤

1. 执行 `npm.cmd test`，确认服务端校验、上游错误和通知逻辑通过。
2. 执行 `npm.cmd run build`，确认 Vue 构建通过。
3. 涉及页面行为时，执行 `npm.cmd run test:e2e`。首次使用先 `npx.cmd playwright install chromium`。
4. 检查 `docs` 下的桌面和手机截图；布局没有拥挤或横向滚动。
5. 真实 AI 或通知相关修改，在自己的配置环境下各做一次手动验证；自动测试使用模拟响应，不能代替真实服务联调。
